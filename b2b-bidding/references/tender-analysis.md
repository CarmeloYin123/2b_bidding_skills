# 招标文件拆解与应答矩阵

## 先建项目事实表

从招标文件、补遗和平台信息提取且标注来源：项目名称/编号、采购人/代理、采购方式、预算/最高限价、投标主体、项目地点、服务期、报名/澄清/保证金/递交/开标时间、递交渠道、格式、签章/加密、正副本及份数。时间统一写明时区；同一事实出现冲突时，标为冲突并以招标文件规定的优先级处理。

## 六遍扫描法

1. **时间与程序**：公告、文件获取、踏勘、澄清、保证金、递交、开标、有效期、签约与履约保证金。
2. **资格与废标**：主体、资质、业绩、人员、社保、财务、纳税、联合体/分包、制造商授权、软件著作权、否决条件。
3. **格式与递交**：目录、章节顺序、原表、封面、签字盖章、扫描件、正副本、密封、电子上传节点、CA、加密、文件格式/大小。
4. **商务与合同**：报价表、税率、价格口径、有效期、付款、验收、违约、赔偿、保密、知识产权、源码、服务、质保、合同变更。
5. **技术与交付**：功能、性能、安全、接口、部署、兼容、实施、培训、售后、人员、验收、交付物与评分。
6. **评分与澄清**：资格/符合性、价格、商务、技术、资信评审标准；每个分值的证据；歧义、矛盾、缺页或需答疑事项。

每一遍都检查正文、前附表、附表、脚注、附件、合同、需求、格式文件以及补遗。不要只依赖目录或 OCR 摘要。

## 应答矩阵字段与判定

| 字段 | 填写规则 |
|---|---|
| 编号 | 可追溯的唯一编号，如 `Q-3.5-02` |
| 原文定位 | `文件名｜页/章/节/表｜原文短句`；不能只写“见招标文件” |
| 类型 | 资格/废标、实质性、格式/递交、评分、商务/报价、合同风险、技术、澄清、内部动作 |
| 优先级 | `P0` 资格/废标或硬截止；`P1` 实质性/高分值/红线；`P2` 其他评分或一般要求 |
| 结论 | 满足、部分满足、不能满足、待澄清、待内部确认；只有证据完整时才能写满足 |
| 应答动作 | 文件章节/表格、应答策略、是否需要偏离说明或澄清 |
| 证据/附件 | 证书、合同、案例、截图、人员材料、审批或责任人提供物 |
| 责任/截止/状态 | 个人或角色、内部最晚完成时间、未开始/进行中/已完成/阻塞 |

将 P0/P1 项逐条回填到最终标书目录和附件，不允许用“一般满足”合并多个不可替代要求。对于“星号、必须、不得、无效、否决、实质性、关键、递交截止、加密、签字、盖章”等表述必须单列。

## 评审与风险输出

在矩阵外附三张短表：

### A. 硬门槛表

列 P0 项、当前证据、缺口、负责人、最晚补齐时间、若不满足的后果。第一项必须是“投标主体/资格与格式是否能通过”。

### B. 评分策略表

列评分项、分值、我方证据、章节/附件、差异化表达、竞争态势、行动。所有高分项都需有可验证事实，不能把推测写成案例或能力。

### C. 红线与澄清表

列知识产权、源码、数据、付款、验收、赔偿、违约、交付范围、平台问题和文件矛盾；写清原文、风险、建议问题、截止、决策人和状态。

## 对本资料库样例的拆解提示

- 已去标识化的完整投标样例：适合练习按“资格审查、商务标、技术标、价格标、资信标”拆解；投标人须知前附表、初步评审、合同、采购需求和格式附件均为重点。
- 已去标识化的询比采购样例：重点关注前附表中的偏差、澄清、保证金、实质性要求、电子递交/CA，以及响应文件格式。
- 历史资料仅用于训练结构，不复用其中日期、金额、客户要求或平台规则到新项目。
