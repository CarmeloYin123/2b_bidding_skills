# 投标文件内容与格式规范性评估

## 审查输入与结论边界

优先取得：被审文件的最终候选版、招标/采购文件和补遗、平台递交规则、项目格式附件、选定历史模板、报价与审批结论。文件版本不明时先列出版本风险。

没有项目招标文件时，只能按“公司基线”和历史模板审查；报告结论必须写明“未验证项目级格式、资格、评分和递交要求”。不得把排版正常误判为可投递。

## 审查步骤

1. **建立基线**：记录标准优先级：项目文件/补遗/平台 > 已批准项目结论 > 公司规范 > 配对历史模板。列出缺失输入。
2. **完整读取**：检查正文、目录、表格、页眉页脚、图片/扫描件、附件、签章页、报价表和文件属性；DOCX/PDF 逐页渲染目检，不能只看导出的文本。
3. **内容审查**：按下表逐项与招标要求—应答矩阵互查。
4. **格式审查**：按下表检查文档层级、版式与递交文件要求；项目模板优先于公司默认版式。
5. **交叉一致性审查**：全局检索项目名称、编号、采购人、投标主体、日期、报价、税率、服务期、人员、案例、旧模板残留和 `【待确认】` 标记。
6. **分级报告**：按 P0/P1/P2 写入问题清单，逐项给出依据和整改动作；没有问题的关键项也列出证据定位。

## 内容审查清单

| 维度 | 必查点 |
|---|---|
| 资格与主体 | 主体、法人/授权人、证书持有人、有效期、业绩、财务/社保/纳税、联合体/分包、证明材料与签章 |
| 技术响应 | 每项需求、性能、接口、部署、安全、兼容、实施、人员、培训、服务、验收均有对应应答与可证明证据 |
| 商务与报价 | 报价总分项、数量、单位、税率、大小写、有效期、服务期、免费/赠送/试用、报价审批与技术/合同边界一致 |
| 合同与红线 | 知识产权、源码、数据、付款、验收、赔偿、违约、质保、服务与已批准结论一致；无越权承诺 |
| 评分与附件 | 评分点有对应章节/附件；附件真实、适用、清晰、完整并符合原表要求 |
| 全文一致性 | 项目名称/编号、采购人、日期、金额、主体、人员、案例、页码、目录和版本无冲突；无旧模板残留或未关闭占位符 |

## 格式审查清单

| 维度 | 必查点 |
|---|---|
| 结构 | 目录、章节顺序、原表、附件、分册、封面、签章位置符合项目格式；标题层级与编号连续且可导航 |
| 默认版式 | 仅在项目无模板时检查：中文宋体、英文 Times New Roman、小四、1.5 倍行距、左对齐、首行缩进 2 字符；一级标题小二加粗、二级标题三号加粗、后续逐级缩小 |
| 表格与扫描件 | 列宽/行高、跨页表头、单元格文字、对齐、边框、图片/印章/身份证明清晰度、无截断或遮挡 |
| 页面 | A4/页边距以项目模板为准；封面、目录、页码、页眉页脚、空白页、分页、文字溢出、图表清晰度均通过逐页检查 |
| 递交 | 文件名、格式、大小、正副本/份数、PDF 转换、压缩包、电子签章、CA/加密、密封/封条、上传节点与回执符合项目要求 |

历史案例的仿宋正文、A4 边距或 Word 样式只可作为项目未指定时的格式参照，不得凌驾于新项目格式。

## 分级与报告格式

| 级别 | 含义 | 典型示例 |
|---|---|---|
| P0 | 可能废标、无法递交、错过截止或突破公司红线 | 资格主体不匹配、缺签章/CA、关键附件缺失、源码/知识产权越界、报价未审批 |
| P1 | 实质性、重大评分、合同或跨章节矛盾风险 | 需求未逐条响应、报价与方案不一致、案例/人员证据不完整、付款/验收条款未确认 |
| P2 | 不直接导致无效但影响规范性、可读性或审核效率 | 字体/间距不一致、标题编号错误、目录页码错误、表格跨页无表头、可读性差 |

按以下格式输出：

```text
审查对象：<文件名与版本>
审查基线：<项目文件/公司规范/历史模板；缺失项>
结论：符合 / 有条件符合 / 不符合 / 待确认
P0：<数量与摘要>；P1：<数量与摘要>；P2：<数量与摘要>

| ID | 级别 | 类别 | 依据 | 定位 | 发现 | 影响 | 整改动作 | 建议责任人 |
|---|---|---|---|---|---|---|---|---|
```

只有不存在 P0、所有项目级必备信息已审到且关键 P1 已闭环时，才可给出“符合”。结论不是法务意见，也不替代业务、技术、销售或用印审批。
