# 项目流程、角色与红线

本文件提供通用 B2B 招投标执行基线。所有项目的审批人、金额阈值、联系人、平台规则与适用流程均须在执行前依据当前授权资料复核。

## 15 阶段标准流程

| 阶段 | 主责 | 完成标志 | 下一步 |
|---|---|---|---|
| 1. 机会预判 | 销售 | 已给出项目类型、客户、金额、截止日、客情 | Go/No-Go |
| 2. 投标决策 | 销售 + 售前 | 已核工期、金额、冲标、资格、知识产权/源码 | 正式发起或退出 |
| 3. 正式发起 | 销售 | 项目情况表与招标文件已发售前，主管抄送/知悉 | 报名准备 |
| 4. 报名准备 | 销售 + 售前 | 主体、平台账号、CA、授权材料已确认 | 保证金/建群 |
| 5. 保证金 | 销售申请，售前跟踪 | 申请、到账/保函或豁免证据齐备；建议至少提前 3 天 | 建群 |
| 6. 建立项目群 | 售前 | 销售及主管、产品、技术、项目经理等已入群；倒排计划已发布 | 审标 |
| 7. 招标文件审查 | 售前统筹，产品/技术/销售协作 | 废标项、需求、合同、付款、赔偿、赠送、知识产权、源码已形成矩阵和结论 | 报价/分工 |
| 8. 报价审批 | 销售形成，售前核对，总部/领导审批 | 成本、人月、标准/历史价格和报价逻辑可解释；当前授权链已批准 | 编标/盖章 |
| 9. 分工编标 | 售前统筹 | 商务、技术、报价、附件有主笔、版本和截止日 | 交叉审核 |
| 10. 交叉审核 | 售前 + 销售/主管 | 矩阵逐项回查完毕；邮件或项目群确认留痕 | 定稿用印 |
| 11. 定稿用印 | 总部招投标接口 | 最终稿、价格、审批、签字/盖章或电子签章齐备 | 封装递交 |
| 12. 封装递交 | 销售确认信息，售前复核 | 正副本、密封、签字、上传、加密、截止时间、回执逐项确认 | 开标/讲标 |
| 13. 开标讲标 | 销售提前通知，售前组织 | PPT/答辩、参会人、统一口径和演练完成 | 结果登记 |
| 14. 结果登记 | 销售 | 中标/未中标及原因已反馈售前 | 归档复盘 |
| 15. 归档复盘 | 售前统筹 | 终版、审批、用印、递交、结果和经验已归档 | 案例/价格/风险沉淀 |

## 四道关口与退出条件

| 关口 | 必须判断 | 不通过时 |
|---|---|---|
| 项目入口 | 工期、金额、客情、竞争、需求可交付性 | 建议不投或上报决策 |
| 资格与主体 | 投标主体、被授权人、证书持有人、资质、业绩、社保/纳税/财务材料 | 补齐前不得承诺投递 |
| 红线与合同 | 知识产权、源码、付款、验收、赔偿、质保/服务、违约责任、合同模板可否修改 | 列风险、澄清并取得明确决策 |
| 报价与审批 | 模块、数量、税率、成本、人月、标准价/历史价格、免费/赠送/试用 | 未完成审批不得盖章 |

少于 3 个工作日、纯冲标、资格无法满足、关键技术不可交付、合同红线无结论、无法按平台要求递交时，不把风险拖到打印或中标后：提出不投、暂停或升级。任何金额或审批阈值均以当前有效授权规则为准。

## 公司原则红线

- 知识产权、数据和源代码的归属、交付范围或二次开发边界不明时，必须单列风险、澄清并取得书面决策；不得作默认承诺。
- 任何源代码、接口或其他技术资料的交付要求均须按经批准的合同与授权边界执行。
- 售前负责识别与控制，不代替合同/法务作最终判断；销售和合同经办/相关职能确认可接受性。
- 免费、赠送、试用、定制开发必须在商务、技术、报价中显式一致，并已获得审批。

## 角色分工

| 角色 | 核心职责 |
|---|---|
| 销售 | 客户与项目第一接口；提前通知、项目情况表、需求/报价初稿、保证金申请、合同模板可修改性、邮寄信息、开标结果 |
| 区域售前 | 项目节奏与整册统筹；建群/倒排、审标/分工/整合、协调产品技术、核价逻辑和红线、交叉审核、讲标组织 |
| 招投标支持 | 标书复核、报价/用印流程、打印盖章与资质材料支持 |
| 产品/技术 | 可满足性与技术内容；方案和参数、工作量/成本依据、技术承诺、讲标专业内容 |
| 项目经理 | 实施计划、资源、交付、验收和项目管理可交付性（适用时） |

## 必须留痕的项目证据

保存项目情况表、招标文件及补遗、拆解矩阵、报名/CA/保证金记录、报价依据和审批、合同风险结论、分工与版本记录、交叉审核/销售确认、用印、递交回执/快递凭证、开标记录、结果与复盘。邮件或项目群的明确回复可作为审核确认留痕。
