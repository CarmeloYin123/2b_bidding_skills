# 会话复盘与改进机制

## 可用证据与隐私边界

仅使用用户授权访问的招投标会话摘要、项目工作包中的 `lessons.md`、明确的用户反馈和新加入的参考资料。仅记录匿名化问题模式，例如“两个项目都缺少递交加密核对”；不记录或复述客户、人员、报价、合同、证照、源代码或完整项目内容。

## 触发条件

满足任一条件时启动 `$bid-skill-maintainer`：

- 两次及以上独立项目/会话出现同一类漏项、误路由、格式问题或用户反馈；
- 用户明确要求完善、纠正或复盘该 skill；
- 新的公司流程、模板、招标案例或工具能力进入参考包；
- 自动安全检查发现来源文件过期、相互冲突或已有引用失效。

未满足条件时不改动 skill。

## 变更边界

| 变更类别 | 处理方式 |
|---|---|
| 触发词、路由、检查项、示例、模板索引、格式/工具步骤 | 可基于两项独立证据做最小变更，并记录验证 |
| 公司政策、审批阈值、联系人、资质、价格、人月、法律/合同、知识产权、源码 | 仅提出待确认提案；取得当前任务明确授权并有新权威来源后才更新 |
| 删除历史规则、改变主/子 skill 边界、覆盖大量内容 | 先提出变更说明、影响范围和回滚方案，再等待确认 |

## 改进日志与验证

在 `references/skill-improvement-log.md` 追加：日期、来源类型与日期、匿名化观察、受影响 skill、改动摘要、风险、验证样例、结果和回滚信息。不要在日志中复制会话原文。

每次变更后：检查所有交叉链接、重新生成受影响 skill 的 UI 元数据、运行 `quick_validate.py`，并用去标识化样例回放受影响工作流。回放失败时回滚本次改动并记录原因。
