# 招投标 Skill 改进日志

仅记录去标识化的改进证据和变更摘要。

## 2026-09-16 — 响应文件版式与技术素材编写机制

- 来源：用户明确提供的响应文件版式要求，以及“基于白皮书、PPT、XLSX 等资料编写技术方案、就近插图并批注技术缺口”的授权需求。
- 匿名化观察：默认版式规则分散在模板库和审查清单，技术素材—招标条款—对客内容之间缺少统一的来源映射、图片控制和内部核验批注机制。
- 受影响 skill：`b2b-bidding`、`bid-tender-analysis`、`bid-authoring`、`bid-compliance-review`。
- 改动：新增共享《响应文件编写标准》；统一默认宋体、六级标题/正文的字号、对齐、缩进、段前段后和行距；要求先完成技术条款—资料/图片—响应章节映射；明确图文就近、来源可追溯和客户信息隔离；将未满足/待核验项改为内部核验版中的真实 Word 批注，对客清洁版必须无批注残留。
- 风险：低。未变更公司政策、审批阈值、报价、资质、合同结论、知识产权或源码边界；仍以当前项目招标文件、补遗、平台和指定模板优先。
- 验证：运行受影响 skill 的结构校验；确认共享标准存在且被总控、编写、审查和模板库引用。
- 回滚：删除《响应文件编写标准》并恢复受影响 skill、模板库、项目工作包和审查清单的前一版本。

## 2026-07-20 — 模块化重构

- 来源：用户授权的 skill 架构评审与改进请求。
- 匿名化观察：拆标、编标、规范审查、递交管控的输入/输出差异较大；单一 skill 的触发范围和默认提示不够聚焦，且质量规则有重复维护风险。
- 改动：将 `b2b-bidding` 收敛为总控；新增拆标、编标、规范审查、递交管控和 skill 维护五个同级 skill；新增项目工作包、会话复盘机制，并将递交门禁与共用规范性检查分离。
- 风险：低。未变更任何公司政策、审批阈值、联系人、价格、法律结论、知识产权或源码规则。
- 验证：运行 skill 结构校验、检查子 skill 的引用路径与无 TODO 占位；后续以去标识化案例回放各子流程。
- 回滚：删除五个新增子 skill，并恢复总控与递交质量门的前一版本。
