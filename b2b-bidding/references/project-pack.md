# 招投标项目工作包

在用户指定的项目目录维护一个项目工作包。它是总控和所有子 skill 的唯一事实载体；不要把原始招标文件、盖章文件或历史模板移动到此处。

## 建议目录与最小文件

```text
<项目目录>/
├── source-manifest.md         # 来源、版本、日期、是否已完整读取
├── project-facts.md           # 项目名称/编号、主体、时间、平台、角色、状态
├── requirements-matrix.md     # 招标要求—应答—证据—责任—截止—状态
├── evidence-register.md       # 资质、案例、人员、报价、审批及证据定位
├── approval-log.md            # 报价、合同、红线、审核、用印等确认留痕
├── review-report.md           # 项目/公司/模板三维符合度与 P0/P1/P2
├── submission-log.md          # 冻结、递交、回执、开标、结果和归档
└── lessons.md                 # 项目复盘的去标识化经验
```

不需要的文件可标为“不适用”，但不可静默省略。历史案例或用户原件保持只读；工作副本与最终递交版在 `deliverables/` 或用户指定的目录保存。

## 版本和证据规则

- 每个事实标注来源文件/会话、版本或日期、定位和确认状态。
- 对招标文件、补遗、最终候选标书、报价与审批记录使用稳定文件名和版本号；发现冲突时保留冲突而非覆盖。
- `requirements-matrix.md` 是拆标后的唯一需求基线；编标和审查都必须回链到它。
- `review-report.md` 必须区分项目符合度、公司红线符合度和模板保真度。
- `lessons.md` 只保留去标识化问题模式和已验证改进建议；不得复制客户、价格、联系人或敏感证据。
