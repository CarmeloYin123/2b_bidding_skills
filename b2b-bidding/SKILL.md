# B2B 招投标总控

将此 skill 用于全流程项目统筹，而非单独的拆标、编标、审查或递交任务。先建立事实和项目工作包，再路由到一个或多个专用 skill。

## 统一规则

按以下优先级处理冲突：项目招标/采购文件、补遗、答疑、平台与指定模板 → 已批准的项目级报价/合同/法务结论 → 公司流程和格式规范 → 配对历史案例。

历史案例仅用于结构、版式、表达粒度和已核实的能力描述。不得照搬客户信息、项目编号、报价、人员、业绩、合同、截图、数据或未经确认的承诺。未知信息仅在项目工作包记录为待确认；技术方案内部核验版须在对应应答位置添加真实 Word 批注，对客正文不得出现 `【待确认】` 或模糊承诺。人员、审批链、资质、价格、平台账号和政策阈值均为动态信息，执行前必须复核。

若工作区缺少 `招投标流程与规范/` 参考包，不得以通用模板宣称“严格遵循历史文件”；要求用户提供最新参考包或模板。

## 建立项目工作包

先阅读 [项目工作包](references/project-pack.md)，在用户指定的可写项目目录建立或更新统一工作包。记录项目名称/编号、采购方式、客户、主体、文件版本、关键时间、递交方式、报价/审批、合同、平台/CA/保证金状态以及所有来源文件。

读取 [公司流程与红线](references/company-process.md)，将证据映射到 15 个阶段。输出当前阶段、状态、证据、阻塞项、下一个关口、责任人与最晚动作。证据不足时写“待确认”，不得把收到招标文件视作已获投标决策。

## 路由专用 skill

| 用户目标或项目需要 | 路由 skill | 主要产物 |
|---|---|---|
| 拆解招标/询比/补遗，建立评分与风险策略 | `$bid-tender-analysis` | 项目事实表、应答矩阵、硬门槛/评分/澄清表 |
| 按项目格式与历史案例编写或改写响应文件，或需从白皮书/PPT/XLSX 提取技术方案与图片 | `$bid-authoring` | 模板选择记录、资料—条款映射、内部核验版/对客清洁版 |
| 审查候选标书的内容、格式和一致性 | `$bid-compliance-review` | 三维符合度结论、P0/P1/P2 整改报告 |
| 判断能否审批、用印、冻结、递交和归档 | `$bid-submission-control` | 阶段门禁清单、放行/阻塞结论、归档清单 |

子 skill 必须读写同一项目工作包。没有应答矩阵时，先拆标；没有选定模板或批准内容时，不得编造完整标书；存在 P0、未审批报价、红线未决或递交要求不明时，不得给出“可递交”结论。

## 四道不可跳过的关口

1. **项目入口**：工期、金额、客情、竞争、可交付性和冲标风险。
2. **资格与主体**：主体、授权人、资质、业绩、人员、证明材料和格式。
3. **红线与合同**：知识产权、源码、数据、付款、验收、赔偿、违约和范围。
4. **报价与审批**：模块、数量、税率、成本、人月、历史/标准价、免费/赠送/试用和当前审批链。

少于 3 个工作日、纯冲标、资格不满足、关键技术不可交付、合同红线未决、报价未批或无法按要求递交时，暂停相应承诺并升级决策。金额阈值等历史规则必须确认仍适用。

## 收尾与持续改进

完成项目后由 `$bid-submission-control` 归档终版、审批、用印、递交凭证、结果和复盘。按 [会话复盘与改进机制](references/improvement-loop.md) 处理重复问题、用户反馈和新资料；只基于授权历史会话和可验证证据更新 skill，绝不把客户敏感信息写入 skill。
